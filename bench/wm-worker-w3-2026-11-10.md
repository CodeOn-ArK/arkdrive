## Design and choices

- Tiles cover the actual root dimensions, including partial bottom/right tiles: 510 at 1920×1080 and 260 at 1280×800. A raw DAMAGE batch only records dirty revisions and invalidation serials. It neither reads pixels nor hashes. Serial checks preserve damage arriving during an in-flight GetImage.
- The mmap is the Xvfb shadow. XWD's big-endian header fields, authoritative `header_size`, colormap count, scanline stride, depth, masks and pixel byte order determine the pixel offset/layout. The ordinary 1920×1080 file has offset 3,232 and stride 7,680; neither is hardcoded. If fbdir is absent, the Fable's GetImage fallback applies. An existing malformed XWD fails closed.
- xorg uses one deferred GetImage over the dirty tile bounding box; dirty tile area exceeding half the screen selects one full-screen request. Both profiles hash RGB content, ignoring the unused X byte. Identical damage cleans tiles without changing their pixel facets. Changed tiles share one facet commit per hash batch.
- A clean incremental observation uses cached integer revisions even with pixels in scope; it produces no frame, hash or X request. Before reporting a new revision, dirty tiles outside the requested scope are settled too. Unsupported tree/OCR requests keep their existing unavailable/uncertain behavior.
- Request one frame with `channels: ["pixels"]`, optionally `scope`, `region` and top-level `scale`. Omit `since_rev` for a full observation when a frame is required even if pixels are unchanged. Frames have the Fable's `{frame, path, rev, rect, scale, space}` fields; `rect` is in `space: "desktop"`. Default long side is at most 1,024; smaller positive scales are accepted; `scale: 1` requires a fitting region.
- Scaling uses nearest-neighbor sampling. A frame point maps to `rect.x/y + floor(point.x/y / scale)`, exactly the source pixel sampled by the encoder. Rational default scales use interleaved column slices to reduce Python work. Frame identity includes revision and transform metadata; PNG filenames hash the PNG bytes. Identical images at different offsets share a file while retaining distinct transforms. Pass `space: "frame:" + frame.frame` or `space: "window:" + handle`; the worker converts. A window point defaults to the action's observation/base revision, with explicit `at_rev` supported.
- `pixels_changed` contains desktop `bbox`, row-major tile IDs in `tiles`, and `windows: [{window, bbox, tiles}]`. Bounds are clipped to the scope/region. This appears without a frame for state/auto observations. Ignore regions exclude only completely covered tiles; partial coverage remains conservative.
- The store quota is 200 MiB. Eviction uses oldest file modification time, preserves files referenced by the last 50 receipts, and pins frames while constructing the current receipt. Receipt protection is restored from the session's journals on restart. If protected files leave insufficient space, a new frame fails explicitly instead of deleting protected evidence. A missing target uses its last known rectangle when available; unavailable/off-screen capture records `capture_error`.
- The 5-second watchdog refreshes window metadata/focus and all pixel hashes through the owner loop. Previously known dirty content is settled before its comparison baseline. Drift increments `resync_drift` in `system.info`; ordinary in-flight notifications are tracked separately.
- No pixel-change success predicates, automatic blind-window escalation, tree/OCR providers or evdev route were added.

## Fix round 1

**Verdict: PASS (headless regression); live gates remain NOT RUN.** Raj owns
the live verification. No display was opened, no scratch session was started,
and display `:0` was not touched. Nothing was staged or committed. Changes in
this round are confined to `wm/ark-worker`, `wm/tests/test_worker_w3.py`, and
this note; there are no new dependencies.

### Root cause

`XState.events()` tested `isinstance(e, damage.DamageNotify)`. In the installed
python-xlib, `Display.extension_add_event()` creates a new class using the
original event class's **bases and copied dictionary**, rather than deriving
from that class. Consequently, the connection's real wire decoder produces
objects named `DamageNotify` which fail that `isinstance` check. Their damage
rectangles were silently ignored; the pixels stayed clean and the next
observation could falsely report unchanged. The old binary-event test decoded
with the imported class directly, bypassing registration and hiding the bug.

This is a demonstrated ingestion drop, independent of event rate. A 5-second
watchdog is insufficient coverage for ordinary observation and explains why
missed notifications can eventually appear as drift. Sparse 6-second fixture
spacing also gives the watchdog time to refresh between changes. The exact
lags in Raj's existing trace cannot be attributed individually without a live
trace; this headless result does not claim to explain every timing sample.

The pump drains queued events without a per-pass event-count cap. Pixel settle
hashes a finite dirty snapshot; its serial check retains later invalidations.
No changes to pump scheduling, settling, mmap reads, GetImage capture, frame
encoding, watchdog timing, or W2 dispatch/verification were needed for the
reproduced defect.

### Change and headless evidence

Match `e.type` against **this connection's**
`self.ev.extension_event.DamageNotify` once the pixel cache exists. The existing
batch coalescing and screen-wide settle then receive the rectangles normally.
There is no extra X request, idle hashing, or polling timer.

Four new tests use a fake byte transport with python-xlib's actual extension
registration, response parser, and event queue, followed by the real
`AsyncX.pump()` → `Worker.ingest()` → observe path:

- Registered DAMAGE at two different extension event codes marks the exact
  tiles without hashing during ingestion. The registered class is explicitly
  checked to be unrelated by inheritance to the imported `DamageNotify`.
- 100 full-frame paints at simulated fixed **80 ms** intervals each reach the
  very next observation's pixel delta. Every paint's six DAMAGE rectangles
  follow 300 unrelated events across multiple transport reads, including the
  DAMAGE `more` flag. No watchdog runs during the simulated eight seconds.
- 100 paints accumulate behind unrelated traffic while the owner is behind.
  After painting stops, one ingestion/observation drains the backlog and
  reports the final pixels without a watchdog or driver action. The subsequent
  idle observation performs no hash or X request.
- The GetImage profile receives registered wire DAMAGE, defers the response
  until a fragmented binary GetImage reply completes, then reports the change.
