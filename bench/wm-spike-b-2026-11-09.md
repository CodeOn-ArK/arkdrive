## Findings that change the design inputs (Phase 0)

1. **Host exclusion mechanism is seat assignment, not ID_INPUT suppression.** A 99-order udev rule clearing `ENV{ID_INPUT}` did nothing observable: `/usr/lib/udev/rules.d/60-input-id.rules` runs the `input_id` builtin whenever `ID_INPUT` is empty, and even pre-setting `ID_INPUT="0"` in a 49-order rule is overwritten — the udev database still shows `ID_INPUT=1` on the virtual nodes. What actually excludes the devices is `ENV{ID_SEAT}="seat-arkdrive"` + `TAG+="seat"` in a pre-60 rule: logind then never offers the devices to the seat0 session, and the host server never enumerates them. (Without it — run 1 — the host **did** enumerate them, albeit as floating slaves.) Broker/device-helper code should treat the host `xinput list` (or logind session device list) as the ground-truth exclusion check, not udev properties. `LIBINPUT_IGNORE_DEVICE=1` set in the same rule did not survive into the final property set either.
2. **`-sharevts` is required for simultaneous live input on multiple dummy servers.** Without it, starting the second Xorg VT-releases the first: its evdev events still arrive on the node (verified with the node watcher) but the server drops them — pointer frozen, keys lost — **while XI still reports Device Enabled=1**. `xinput enable` fixes the XI flag, not the DDX-level VT gate. With `-sharevts`, both servers' input paths stay live concurrently (diag3: S1 pointer moved after S2 was up; run 10: both sessions typed/clicked in any order).
3. **With `-sharevts`, mask `/dev/dri` per session.** The first server then keeps DRM master, and a second server's platform-GPU (modesetting) probe dies fatally: `modeset(G0): drmSetMaster failed: Device or resource busy`. `AutoAddGPU=false` alone does not suppress the GPU screen on xserver 21.1.22. The launcher therefore bind-masks `/dev/dri/card*` and `renderD*` with `/dev/null` inside a private mount namespace per session server. (GPU qualification is probe 3's problem; the dummy path is software-rendered regardless.)
4. **Session device setup procedure** (now part of the spike harness, belongs in ark-sessiond): config-section evdev devices start as **floating slaves** under `AutoEnableDevices=false`; setup must `xinput reattach` each device to its core master **and** `xinput enable` it, then verify `Device Enabled=1` via `list-props` — and, per finding 2, verify by an actual probe event, not the flag alone. Device *names* in `xinput list` are the config Identifiers (`kbd`/`ptr`), not the evdev product names; routing evidence belongs in the server log's `evdev: …: Device: "<path>"` lines.
5. **Pointer determinism:** `xinput set-prop <ptr> "Device Accel Profile" -1` yields exact 1:1 relative motion (click landed on the exact target pixel; a (137,89) move measured (137,89)). Default evdev acceleration measurably distorts deltas (~1.6×, run 5).
6. **Bench hygiene:** run 1's baseline was silently poisoned by a parallel smoke test that had left a first `mkdevs` instance (and its 4 devices) alive in the same directory minutes earlier — the two instances shared the command FIFO and cleanup pidfiles named `sudo` wrappers instead of the real processes, so the first instance survived "cleanup". The harness now (a) refuses to start unless a preflight scan shows zero stale ArkDriveB devices/helpers, (b) has helpers record their own pids via an `exec` launcher, and (c) sweeps by full-path pattern in cleanup and verifies zero devices remain. Phase 0 benches running in parallel need separate working directories per spike.
7. Harness (not platform) defects fixed along the way, for the record: `input_event.value` is `__s32` — packing it unsigned made the helper throw on every negative pointer delta (`ERR 'I' format requires 0 <= number <= 4294967295`); a root-created command FIFO was unwritable by the driver script; udev's async add processing can reset node permissions after creation, so the 0666 chmod for the readback watcher is re-asserted after a settle delay; the AT-SPI probe originally used a non-existent `queryInterface` call and reported every entry as empty (false text failures in runs 4–6) — text is now read via role match + `queryText()`.
