## Defects found and fixed

### Spec / staged-contract reconciliation

- Used the reconciled/user contract over illustrative Fable receipts: success/failed/partial/unknown and complete, rather than completed/rejected/done. A suffix uses requested not_reached plus stop_reason prior_step_stopped, with an explicit not_observed effect rather than null.
- Used one chord (1–4 keysyms), physical typing through 2,000 characters, click counts 1–3 with 60 ms gaps, focus 200 ms × 2 and XI2 50 ms acknowledgement. These supersede conflicting older multi-chord, 200-character paste, 1–2 click/80 ms and 100 ms/one-focus forms.
- R6 defaults do not authorize reaction. W2 cannot compute whole-field text readback, so missing text expect is invalid_expectation. The explicit user allowance for an evaluable state-class text predicate is supported; explicit tree readback still honestly returns unknown/provider_degraded. No weaker predicate is substituted.
- W1 has bare session profile names, not qualified application-build profiles. W2 hashes its effective fixed routing/input/shortcut settings for non-null profile_hash; it does not fabricate application hashes, Thunar semantic classification or route-table learning. Text uses the profile's explicit select-all shortcut and session-server key mapping. Provider/profile qualification stays with later steps.
- The startup self-test must obey preserved PAUSED/HUMAN authority from W1. It defers rather than injecting through a closed control page, then runs after an explicit owner resume. A failed diagnostic reports channel down; the worker remains available for observation/control.
- Control CLI remains the sole control-page writer. Awaiting reconciliation closes logical mutation admission; it cannot be cleared by an attach, an old-state read or merely clearing a session fence. Owner epoch transition, new lease and fresh observation are required after effect/delivery proof. No visual_review continuation is built.

### Harness

- Corrected missing explicit target in a focus-repair test whose cached focus was intentionally empty, and cleared the first run's expected window before testing a second focus failure. Otherwise already-satisfied rejection correctly precedes focus repair.
- Corrected the keysym test's import and its legacy-Euro expectation. Server-map conversion covers legacy and Unicode keysyms using the installed pure conversion library.
- The final static checker initially mistook the internal Engine.run generator for subprocess.run. Qualified process-launch checks fix that harness false positive.
- Fake X now distinguishes application writes (requiring durable intent/arm) from a journaled diagnostic release after self-test preemption. A missing raw acknowledgement does not imply a server key-up was unprocessed; shutdown assertions check both independently tracked and fake-server state.

### Product

- Tracks possibly pressed keys/buttons until acknowledgement, with QueryKeymap fallback for keyboard releases. Failed releases fence; they are never silently forgotten. Cleanup remains release-only through gate/epoch changes and storage failure.
- Keeps focus repair as confirmed targeting evidence, so the repair is not confused with an unexpected application focus change. Checks focus/modal between macro groups, retains focus leave/return uncertainty, and permits tracked releases after an expected dialog opens.
- Records dispatch revision before the first possible write, not after flush. A synthetic effect during flush exposed why the latter can hide a focus gap.
- Resolves a drag destination before any move/press, so an unavailable ref cannot dispatch a prefix. A disappearing focus target ends as target_not_found instead of an internal exception. Pointer modifiers follow the act-spec left-modifier allowlist.
- Pointer-only move now uses the same ownership hit-test as other pointer operations. Geometry changes during preparation prevent a later press. No coordinates are clamped or guessed.
- Validates and fsyncs repaired storage before permitting a fence clear or receipt recovery; a malformed tail keeps F3 closed. A readable intent before a corrupt tail produces unknown with incomplete history.
- Reserves IDs across intent fsync failure and persists known pending outcomes after storage repair without dispatch. Reconciliation records supplement, rather than replace, the immutable receipt.
- Preserves release-only shutdown and diagnostic cleanup, paused-start authority, and unavailable-provider honesty. No host or sibling fallback was added.

## Fix round 2

Scope: the stopped-batch receipt corruption and missed click/title verification
reported by Raj from live action `c3-a1`. This run opened no display or session
and made no live acceptance claim. Raj reports round 1 live passes for SELFTEST,
C6, C1 (5,142/5,142 key events, exact text, sibling and host clean), E7, C5,
C2 (100/100), and D5; those are supplied evidence, not checks repeated here.

Root causes:

- **Receipt corruption:** `Engine.run`'s outer `ActError` handler unconditionally
  selected `receipt["steps"][0]`. An exception escaping an active step's error
  handler therefore rewrote the already-verified first step as failed and changed
  the stopping-step pointer to that first step. It now retains the active step;
  only admission failures before the step loop select the first step. It also
  preserves a verified disposition/effect and retains accepted dispatch records.
  `stopped_step` remains the caller's step ID, and `stopped_at` remains the existing
  one-based `i` field.
- **Verification stall:** verification relied on event-cache updates until the
  full step deadline. A missing/delayed `PropertyNotify` therefore exhausted the
  window even when the application's title had already changed. Worse, the
  final-look transport called back after one barrier and a pointer read, while
  reconcile callbacks could still be queuing/awaiting metadata replies and
  follow-up snapshots. That callback did not establish a fresh title sample.
  A timed-out final refresh could also escape the step's exception handler and
  trigger the receipt-corruption path above.
- **The three click attempts were not three clicks:** the existing dispatcher
  records pointer motion, button press, and button release separately. Its
  macro-reissue branch already permits only move/focus. No click replay branch
  was found or added. The independent fake input log now asserts exactly one
  press and one release over both successful and full-timeout verification.

Changes:

- `wm/worker_act.py`: preserve active-step attribution in the outer stop handler.
  For an unconfirmed predicate, refresh after the initial 40 ms observation
  window, then at most every 100 ms after a read completes. Retain the bounded
  final fresh look at the deadline. A final read timeout becomes honest
  `unknown` / `provider_degraded`, without escaping into another dispatch or
  overwriting a prefix record. Query completion/timeout cancels refresh polling.
  Move/focus reissue behavior is unchanged.
- `wm/worker_xtest.py`: after reconcile, asynchronously drain metadata requests,
  including requests generated by earlier callbacks and repeated snapshots,
  before deriving/committing state and completing the pointer read/callback.
  This uses the existing server `_NET_WM_NAME` / `WM_NAME` sampler. Cancellation
  prevents an abandoned read from continuing to enqueue barriers.
- `wm/tests/test_worker_w2.py`: add seven deterministic regressions. A deferred
  fake server drives the real `XState.reconcile`, refresh/snapshot, and transport
  refresh code without delivering `PropertyNotify`. It deliberately delays title
  replies beyond the first barrier and can stall a reply indefinitely. Tests
  cover a four-step batch stopping on step 3; a nested read error retaining step
  3 attribution and the durable verified prefix; prompt title verification with
  one click; absent effect over the full 5 s with one click; a fresh final-look
  title reply; follow-up snapshot drainage; and a stalled fresh read producing
  unknown, with one click and no orphan barrier loop.

## Fix round 3

Scope: B1 (many-window verification starvation) and B2 (same-session worker
restart after SIGKILL). Raj's round-2 receipt bookkeeping is supplied as
live-verified good; the active-step attribution fix is retained. This run used
fake X only and opened no display, session, listener or input device.

Root causes:

- **B1:** round 2's transport fallback called whole-session `reconcile()` and
  waited for both the global metadata queue and every refreshing window to
  drain. Client/frame discovery and ongoing events added further snapshots.
  With ~150 windows, unrelated metadata could consume the entire step window.
  Predicate evaluation also required whole-session coverage, so merely narrowing
  the transport wait would still leave verification unknown during unrelated
  refreshes.
- **B2:** startup treated any WM selection, supporting-window property or root
  redirect mask as a foreign WM. A prior generation's surviving Openbox took
  that same refusal path. The inspected worker metadata did not persist the
  spawned WM's identity, so the fix also adds a durable WM identity record.

- `wm/ark-worker`: add an independent targeted sample. It reads named predicate
  windows, the resolved step target, focus and pointer state. For unscoped match
  predicates it discovers client/root IDs and probes only the requested title,
  class and type classifiers; only matches receive full snapshots. Fresh
  negative classifiers update old cached matches too. The sample counts its
  own requests, including discovered matches and recursive ancestry replies;
  unrelated refreshes and event-triggered repeats do not gate completion.
  Event-driven cache refresh and whole-session observation coverage remain.
- `wm/worker_xtest.py` and `wm/worker_act.py`: pass the predicate and target to
  that sample. Verification and its final transition check accept the completed
  sample's coverage without requiring unrelated metadata to drain. Preserve the
  40 ms event window, bounded 50 ms reads, periodic fallback, final look and
  timeout cancellation. Receipt attribution and click dispatch/retry rules are
  unchanged.
- `wm/ark-worker`: persist `wm_pid` and process start time in session-local
  `openbox.json` immediately after spawn, before baseline/self-test, and include
  them in ready `worker.json` metadata. Adoption verifies the recorded PID is
  alive with the same start time, exact Openbox/config command line, session
  markers and display, and verifies the advertised X WM owners' `_NET_WM_PID`.
  A matching WM is adopted without spawning another; absent/dead/mismatched
  identity with a WM present still returns `wm_already_running`. No WM still
  takes the existing spawn path. Adopted-WM lifecycle handling checks identity
  before signalling and does not try to reap a non-child. Generation creation,
  control-page rebinding and baseline use the existing startup path.
- `wm/tests/test_worker_w2.py`: add 12 deterministic regressions: named-title
  and title/class/type match verification with 150 windows and withheld title
