# Worker W5 build — November 10, 2026

W5 implements the stdlib driver adapter (`wm/ark-act`, shared
`wm/worker_adapter.py`), API loop (`wm/ark-loop`, `wm/worker_loop.py`),
and the 640×360 observe-frame default in `wm/worker_pixels.py`.
The reconciled WORKER-BUILD-SPEC governs the implementation; Fable §5.8
and §5.10 supplied the adapter and worked-example contract.

All build work and verification were headless. No live display, X connection,
D-Bus connection or pyatspi runtime was opened. Neither ark-sessiond nor
ark-worker, nor any session, was started. Tests use fake worker peers,
synthetic cached pixels and fake HTTP responses. Fixtures are untouched.
Nothing was staged or committed.

## Adapter protocol and use

```sh
wm/ark-act mcp --session s1 --images path
wm/ark-act call observe '{}' --session s1
wm/ark-act call act '{"steps":[{"intent":{"kind":"key","keys":["F2"]},"expect":{"kind":"dialog_present","match":{"title_re":"^Rename"}}}]}' --session s1
```

The exact **targeted Codex registration keys** from Fable §5.8 are
`-c mcp_servers.ark.command` and `-c mcp_servers.ark.args`:

```sh
codex exec \
  -c 'mcp_servers.ark.command="/home/ark/arkdrive/wm/ark-act"' \
  -c 'mcp_servers.ark.args=["mcp","--session","s1","--images","path"]' \
  '<task and verification instructions>'
```

This is the registration target, **not a live-confirmed Codex integration**;
Raj confirms the keys and behavior at F1. No Codex driving run was made here.

MCP stdio uses newline-delimited JSON-RPC 2.0 with initialize, initialized
notification handling, tools/list, tools/call and ping. The four tools are
observe, act, wait and done. Tool execution errors use MCP isError content;
protocol errors use JSON-RPC errors. Standard output contains protocol only.
The worker socket remains its existing four-byte big-endian length-prefixed
JSON protocol at SD/driver/act.sock. Run directories use the account database
home, matching ark-worker, independent of inherited HOME. No worker import
or desktop dependency is needed by either new executable.

The adapter attaches and holds its connection-bound lease. Attach revision
metadata is private and never advances the model baseline. Observe adds
since_rev (null for full); act adds lease, fresh action_id and last-shown
base_rev; wait translates timeout_ms to deadline_ms and adds since_rev;
done maps to session.done. Existing required session/generation/control_epoch
fields come from attach. Any returned top-level revision advances the model
baseline; receipt rev.final is rendered as the result's integer rev.

Act requires a prior shown observation. A new CUT/reconnected lease performs
the worker's full-state observation handshake when necessary before act,
without replacing the model baseline. If state advanced, the existing worker
stale-revision check rejects the old base rather than acting on unseen state.
New connections honor the worker's five-second disconnected-lease grace by
retrying attach on the structured lease_held reason for up to six seconds.

After an uncertain act send, recovery reconnects and polls the lease-free
action.get with the **original generation and action_id**, never window.act.
Reattachment happens before the next leased tool. Polling is bounded to
15 seconds; pending and not_found responses do not authorize a resend.
An unresolved ID survives a timeout and blocks a new act: another act call
resolves and returns the previous outcome instead. This also covers a failed
inline-image read before the result can be shown.

The CUT uses exactly the same Adapter implementation. It prints one JSON
object, `{ok:true,content:[...],isError:false}`, or `{ok:false,error:...}` with
nonzero exit. Text content contains the rendered tool-result JSON; frames
remain paths by default. Session selection is --session or ARK_SESSION_ID.
A separate file lock serializes CUT calls; SD/driver/adapter-state.json is
atomically replaced with mode 0600 and fsynced content. It stores generation,
last-shown rev and any unresolved action ID, never the lease or credentials.
A pending ID is saved before any act send. A generation change invalidates
the old revision baseline.

Receipt projection returns batch status/reason, one id/effect/route/reason
entry per step, unexecuted_steps, state_delta and advice, plus action identity,
final revision and failure-frame descriptors. Attempts, intent text,
predicates and raw evidence remain in the worker journal. Worker tree
budgets remain authoritative: full pages ≤200 nodes/16 KiB; deltas
≤40 nodes/2 KiB. The adapter does not truncate rendered trees a second time
and thereby invalidate the worker's ref baseline. Inline mode additionally
returns PNG MCP image blocks, retaining path and coordinate metadata.

## API loop

```sh
# Provider/model/server/key configuration comes only from CU_MODEL_* env vars.
wm/ark-loop --session s1 --task 'Create and rename a folder; verify the result' \
  --max-turns 40 --images path
```

The loop launches ark-act MCP, initializes it, reads its actual tool list,
and forwards model tool calls until an acknowledged done, a failure or the
turn cap. --max-turns can lower the cap; values above 40 still cap at 40.
A turn is one provider completion; all returned tool calls count separately,
and execution stops immediately at an acknowledged done. A model ending
without done is reported as model_stopped_without_done. The JSON run summary
reports turns_used, tool_calls_made, frames_viewed, summed numeric provider
usage fields, max_turns, done status/summary or the failure/cap reason.
Exit 0 requires done status success; failed, blocked, cap and errors exit 1.
Frames count as viewed when inline image blocks have been supplied to a
successful subsequent provider completion; paths alone do not count.

Presets/defaults and overrides follow docs/DRIVERS.md: llama (default),
openai, deepseek, openrouter and anthropic; CU_MODEL_SERVER and CU_MODEL
override the preset. Only CU_MODEL_API_KEY supplies credentials. Validation
runs before starting the adapter or making network requests. The key is
excluded from the adapter subprocess environment, never put in argv, output,
state files or request bodies; it goes only in provider authentication
headers. Errors do not print HTTP bodies, URLs, headers or arbitrary
exception text. CLI parse errors also avoid echoing argument values.

llama/openai/deepseek/openrouter use Chat Completions function tools and
matching tool-call result messages. Anthropic uses Messages input_schema,
tool_use/tool_result blocks, top-level system, x-api-key and
anthropic-version. Inline PNGs translate to data-URL image_url input for
OpenAI-format vision providers, and base64 image blocks for Anthropic.
OpenAI images follow the complete group of corresponding tool replies;
Anthropic images accompany tool_result. DeepSeek's text preset omits image
blocks; path metadata remains. Choosing inline with llama/openai/openrouter/
anthropic assumes the selected model supports vision. Hosted sampling uses
portable fields; llama-only extensions stay with llama. No provider API or
model compatibility was live-tested.

## Frames

Observe defaults to `min(1,640/width,360/height)`: a 1920×1080 desktop yields
640×360 at scale 1/3. Small regions are not enlarged. Explicit scales remain
the requested fraction of native pixels, including scale:1 → 1920×1080.
Receipt evidence for not_observed, contradicted and unknown effects now
explicitly requests scale:1. Tile hashing/identity stays 64×64 in desktop
pixels before resizing. Existing rect/scale/frame transforms still map
frame pixels to native desktop coordinates.

Three W3 tests retain their existing coverage with expectations updated for
the intentional default-size/native-scale change. No worker wire format,
predicate or receipt schema changed. W4 review proposals P2–P4/P6–P8, OCR,
evdev and paste remain outside this build.

## Fix round 1

The live F2 failure supplied by Raj was a turn-2 HTTP 400 with the llama
preset against the on-box 8192-token llama.cpp context: the request reached
8338 tokens, including a 9734-character observe result. This fix changes only
model-facing rendering and history. Worker socket messages, predicates,
receipts, journals and fixtures retain their existing full fidelity.

The shared MCP/CUT observe renderer now projects `pixels_changed` into
`bbox`, `windows` and a numeric `tiles` count. Per-window entries keep their
window handle and bbox, with their tile lists also replaced by counts.
Provider entries retain state/reason; `apps` and `window_status` preserve
app/window identity with state/reason only at each level. Duplicate window
lists, pid, counters, probe timing and nested diagnostic detail are omitted;
the existing fallback capability list remains. Top-level `coverage` and
`channels_used` are omitted. All other observe fields, including complete
tree/state content, are unchanged. Act and wait rendering is unchanged.

The loop applies two history rules:

1. Appending a new observe replaces every earlier observe's entire content
   with one text block containing `{"rev":<known rev or null>,"superseded":true}`.
   Act/wait content and the latest observe remain intact under this rule.
2. Before each provider call, the guard estimates tokens as the sum of
   serialized history and tool-definition characters divided by three.
   `CU_LOOP_TOKEN_BUDGET` overrides the preset default: llama uses 7000;
   other presets use 0, which disables the guard. While over budget, the
   oldest remaining act/wait result content becomes one text block containing
   `{"superseded":true}`. The two most recent tool results are always
   protected, observes are skipped, and already-stubbed results are skipped.
   If no eligible content remains, the request is sent as-is even if still
   over budget. Invalid/negative budget settings fail configuration before
   any subprocess or network request.

Tool-call/result envelopes remain paired. Inspection and a headless loop
test confirm that adapter revisions, base_rev and action-ID allocation use
adapter state and immediate RPC results rather than history text. Inline
frames removed by compaction before delivery do not count as viewed.

## Fix round 2

Raj's live F2 evidence identified a reconciliation deadlock: after an uncertain
act, repeated default delta observes could not satisfy the worker's full,
settled session-scope reconciliation requirement. Separate runs repeated an
invalid act ten times and hit the provider's 120-second HTTP timeout during
local generation. This round addresses those supplied findings in the adapter
and loop only.

The adapter now performs exactly one automatic observe through its ordinary
observe path with `full:true` and `scope:{kind:"session"}` when an act receipt
has advice `observe_first`, reason `awaiting_reconciliation`, or status
`unknown`/`contradicted`. It never resends the act. A full settled observation
without `resync_required` adds `reconciled:true` and `state_now`, using the
Fix round 1 observe projection. The observation advances and persists the
adapter revision; the older receipt revision cannot overwrite it. This also
applies to receipts recovered through `action.get`. Failed or unsettled reads
return `reconciled:false` with the original receipt/advice; successful but
unsettled reads retain ordinary observe revision bookkeeping. The kill switch
still stops execution. Other success/failed receipts trigger no automatic read.

The act description includes a three-step create-folder JSON example: open
and bind the dialog/entry, type into the bound entry, then press Return and
expect the new item in the folder listing. The observe description explicitly
explains automatic reconciliation and that `full:true` is unnecessary for
correctness.

The loop tracks consecutive failed calls by tool name and canonical arguments
JSON. MCP `isError`, top-level error fields and JSON text error fields count as
failures. The third identical failure adds the requested user-role hint once
per streak; a changed call or success resets the counter. Hints follow the
complete group of tool replies to preserve provider call/result pairing.
`CU_LOOP_HTTP_TIMEOUT` configures provider HTTP timeout in seconds, accepting
positive finite values (including fractional seconds). Missing or invalid
settings fall back to 120 seconds.

## Fix round 3

Raj's live F2 runs 4–6 supplied the cause: every model act failed with
`confirm_required` because the published act step schema advertised `risk`.
The model supplied `"risk":"low"`, but declaring any risk deliberately requires
human confirmation at the worker gate. This was a schema-advertised safety
field trap: offering a driver control to the model poisoned otherwise ordinary
batches. The worker gate is correct and remains unchanged; the fix belongs in
the adapter's model-facing surface.

The act step schema no longer publishes `risk` or `allow_stale_pixels`. The
adapter also rejects either key by presence, regardless of value or step
position, before attachment, pending-action recovery, action-ID allocation or
state persistence. MCP returns `isError` with text naming the offending field,
stating it is not settable through this tool and directing the model to resend
the batch without it. No worker request is made for the rejected batch. CUT
uses the same validation and its existing JSON error/exit behavior. Clean
batches retain their step bytes; all other validation, descriptions and the
three-step create-folder example remain unchanged.

## Fix round 4

Raj's live F2 runs 7–9 supplied the diagnosis: the local 27B model invents
expect kinds or sends invalid mutating step forms, then receives no guidance
about the valid form. The platform is verified healthy by the scripted
canonical create-folder batch and the strong driver's F1 3/3 result. One run
also acted on an empty startup observation before the application mapped.
This round uses that evidence without repeating live diagnosis.

The loop SYSTEM now names all 13 requested expect kinds, requires tree
expects to include `"provider":"atspi"` and a role/name/name_re selector,
and explicitly explains that mutating steps need a strong expect or are
refused before dispatch with `invalid_expectation`. It directs the model to
fix the step FORM after `invalid_expectation` or `invalid_params` rather than
resending unchanged. An observation with no windows now instructs the model
to wait briefly and observe again before acting.

The adapter appends the requested JSON hint as one additional text content
block for an act worker error `invalid_params`, or a receipt whose batch
reason or any step reason is `invalid_expectation` or `invalid_params`.
Receipt JSON remains byte-identical; the hint is outside the receipt and
does not affect revision parsing, recovery or reconciliation. MCP retains its
existing error block and `isError`; CUT retains its failure envelope and exit
status, adding content only for the qualifying worker error. Success and
unrelated failures receive no hint. Tool definitions, schemas and the
three-step create-folder example remain unchanged.
