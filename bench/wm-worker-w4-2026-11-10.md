## What was built

`wm/worker_atspi.py` is a persistent provider child, launched before worker
readiness. Only this child imports pyatspi. Its environment takes both bus
addresses, display, home and runtime directory from the session record;
missing bus addresses or a display outside 91–120 refuse launch. It never
uses X root properties for accessibility discovery. Children retain both
sessiond markers and log to the session's `logs/atspi-provider.log`.

The child has a GLib/IPC loop and one outstanding application job per app.
Application RPC runs in separate daemon threads; the IPC/event callbacks do
not call into an application. Frames use four-byte network-order lengths and
JSON. `wm/worker_tree.py` owns the worker's nonblocking transport, deadlines,
supervision, per-app breakers, snapshots, refs, selectors and predicates.
The worker polls this transport in its existing event loop; no observation
or action waits synchronously for a provider reply.

The tree cache supplies `lines/1`, stable refs, continuations and bounded
added/changed/removed deltas. Filtering follows showing+visible and the
name/text/interactive/descendant inclusion rule. Unnamed single-child
containers flatten; unnamed interactive controls remain. Names and text are
JSON quoted so a newline cannot manufacture another tree line. Rendered text
is capped at 80 Unicode characters; whole-field predicate text is retained.
States are restricted to the six specified states and bounds use desktop
pixels. The initial bounded walk also determines the usable/empty probe.

`window.observe` supports explicit tree requests and adds a usable focused
(or scoped) tree to auto observations. Tree facets participate in revision
checks only when tree is requested or auto is selected. State/pixel scopes
retain their prior comparison path. A pending, degraded or down tree leaves
state and explicitly requested pixels available; auto supplies pixels when
its tree is unavailable. Provider health includes per-app reasons and the
implemented fallbacks: state, pixels and keyboard. OCR remains W7.

All eight already-classified tree predicates now evaluate:
`node_present`, `node_absent`, `text_equals`, `text_contains`, `node_state`,
`item_present`, `item_absent`, and `scroll_value`. Requires for live/enabled
refs, selected/editable refs, exact text and modal role are functional.
Selectors support exact case-sensitive name, regex name, role and descendant
scope; ambiguity rejects before dispatch, including an admission check
against the available cache. A late ambiguity never chooses an arbitrary
node. Ref targets use the existing stale revision failure path.

Ref/selector clicks resolve current bounds and use their center on the
existing session-local XTEST physical route. Text focuses physically and
uses the existing keyboard macro. Explicit invoke selects the named observed
AT-SPI action, otherwise `press` when available, otherwise the first action.
The child checks generation, control epoch, gate state and deadline directly
before invoking. Acceptance is delivery evidence; a fresh application-state
predicate still has to verify the effect.

A text step targeting an editable readable node computes whole-field
`text_equals` when expect is omitted: literal replacement, or insertion into
the sampled caret/selection range. An unfocused field is clicked physically;
insertion restores the sampled selection with physical keys. Missing
insertion-position metadata rejects the computed default. Explicit expect
wins, and targets without semantic text retain W2's explicit-expect rule.
No submitted text is automatically replayed (R2).

The adopted exact rename dialog classifier and verified cross-step bindings
support the D1 batch shape: selected item's name equals the unique enabled
editable field's initial value, semantic dialog root, exact enabled `Rename`
and `Cancel` buttons, and the permitted X window family. Bindings are exported
only by a verified step. Later requires reuse the same classified dialog and
entry identity after the text changes. No fuzzy title or control matching is
introduced.

`wm/fixtures/fx_log` preserves its existing flags and SIGUSR1 hang trigger.
`--hang` additionally blocks the GTK main loop three seconds after startup,
indefinitely while the process remains alive and terminable. After its first
paint it writes one `widget_inventory` JSONL record from GTK/ATK-side widget
roles, accessible names, allocation bounds translated to desktop coordinates,
parent identities and visibility. This oracle uses no worker refs or AT-SPI
client snapshot. Existing input, text, click and paint records remain.

## Design choices and limits

| Clause | Implementation choice |
|---|---|
| F §3.5 matching; F §3.8 per-app isolation | App health keys use `_NET_WM_PID` where available, falling back to the X app/class identifier. PIDs distinguish independent instances with the same class. The PID is retained privately from the existing X metadata read; legacy state window objects gain no field. Child frame matching prefers that PID, then largest overlap. |
| F §3.8; W4 per-call deadline | The worker applies a conservative 250 ms end-to-end deadline, including IPC scheduling. libatspi also has a 250 ms call timeout; a snapshot checks a 240 ms cooperative walk deadline between calls. One app has one outstanding job, so a timed-out job cannot accumulate a queue. Other app jobs use independent threads. Actual libatspi/server scheduling and latency await live B5. |
| F §3.8 recovery | Two consecutive failures/breaches or one outstanding call over one second degrades the app. Recovery delays are 1, 2, 4, 8, 16, 30, 30… seconds. A successful recovery clears the app's cached probes and rebuilds its windows. The original outstanding job must finish before a recovery job can run; probes never queue behind it. |
| F §3.8 child versus app failure | Only stalled work causes IPC heartbeat traffic. A responsive child can retain a degraded app without restarting healthy apps. An unanswered child heartbeat or child exit kills/reaps and restarts the child with the same capped backoff. Thirty seconds of child uptime resets the restart streak. All previous child refs and cursors become stale. |
| F §3.3 cheap reads versus silent hangs | Cache reads never rebuild an unchanged tree. Tree/auto consumers may request one lightweight application health round trip per second; this detects a GTK main-loop hang even without a tree notification. State-only consumers do not request these probes. Repeated immediate cached reads perform no provider writes. This separates cached snapshot reuse from liveness testing; live idle accounting must distinguish explicit state scopes from active tree liveness checks. |
| F §3.5 one build per change | Events coalesce into per-window dirty flags, with one app job in flight. Invalidation serials prevent an old reply from clearing a newer change; a build overlapping a change is discarded and rebuilt for the newer version. X geometry changes also invalidate bounds once. Snapshot reads and cursor pages use the cache. |
| F §3.5 refs; W4 stale targets | Refs are worker-wide monotonic `n<int>` tokens keyed to bus/object path and included parent. Ordinary field changes preserve refs; explicit child removal, parent changes, and provider restart invalidate them. Action admission/dispatch additionally guards the relevant tree revision. A former ref from a restarted child cannot verify absence or reconcile an old effect. |
| F §3.5 output budgets | Full pages cap both nodes (200) and serialized UTF-8 tree payload (16 KiB). Cursor tokens bind to window and cached revision and are reusable. Deltas cap 40 entries and 2 KiB; older baselines, over-budget deltas and reordered surviving refs get full pages. One previous snapshot is retained. An individually unrenderable line reports scoped degradation instead of issuing a non-progressing cursor. |
| F §3.5 bounded traversal; predicate completeness | Internal complete walks cap at 10,000 objects, 4 MiB IPC and 65,536 characters per readable field. Exceeding a walk/IPC/text budget fails the app call instead of using a partial enumeration as absence evidence. The semantic inventory retains offscreen items even though lines/1 omits them; item absence checks the complete container inventory. These internal limits are implementation bounds, not measured targets. |
| W4 exact-one selectors | Zero matches fails selector predicates, including a selector-form absence predicate, as requested. Ref absence can verify only a previously issued current-provider ref. The existing named `item_absent:{container,name,role}` form instead checks zero matching items in a live, completely enumerated container. These are deliberately distinct absence forms. |
| R1; W6/W8 boundary | Physical operations retain W2's current XTEST route on both profiles. Evdev remains W6; automatic semantic/paste fallback remains W8. Only explicit invoke uses AT-SPI actuation in W4. |
| R6 and existing-call compatibility | New defaults apply only to resolved editable AT-SPI targets. Explicit expectations and prior non-semantic behavior stay unchanged. A provably identical whole-field text replacement can finish without dispatch; an unrelated already-true predicate cannot skip an edit. |

## Fix round 3

Implemented F5–F6 against Raj's November 10 Thunar heap-corruption evidence
and Fable review §2 risk 2. This section supersedes the earlier threading
description. **B4, B5, D1, the thread soak and all other live checks remain
NOT RUN; Raj owns their re-runs.** No live display, X connection, D-Bus
connection or pyatspi runtime was opened; neither ark-sessiond nor ark-worker
was started. Fixtures and existing tests were not modified. Nothing was
staged or committed.

Previously, `main().pump()` started a daemon thread for each application
job. Those threads called the registry and accessible interfaces while the
GLib thread handled AT-SPI event metadata on the same library connection.
The child now has one binding owner: the thread running the GLib main
context. Startup/imports, timeout configuration, listener registration,
event callbacks and every complete Backend operation execute there. The IPC
source admits jobs to a FIFO, retaining one flight per app, and executes one
job per turn before returning to GLib. There are no application job threads
and no child watchdog thread calling the binding. IPC is the submission
boundary; the worker continues submitting and expiring work asynchronously.

| Item | Change and headless evidence |
|---|---|
| F5 — single-threaded binding access | `wm/worker_atspi.py` removes the per-app thread launch and dispatches queued snapshots, probes, inventory walks and invokes on the GLib owner. Registry/desktop lookup, property reads, cache clearing, iteration, text, selection, states and actions therefore share the event/listener thread. A guarded fake binding records every property, method and iterator entry, releases the GIL during entries, and raises on overlap. Concurrent producers submit two snapshots, a probe and an invoke while queuing an event burst; a complete inventory follows. All entries, including listener registration and event identities, have the GLib thread id and zero overlaps. State-set and accessible identity reads also pass through individual call timing. A separate fake 210 ms state read reports a 210 ms maximum and a breach. Binding reads occur outside bookkeeping locks so reentrant event attribution can take those locks. |
| F5 — deadlines and supervision | Walk budgets remain 2 s and libatspi timeouts remain `(250, 2000)` ms. Call timing begins when the job executes; waiting in the FIFO does not become app-call time. Debounce, snapshot publication, authority checks immediately before invoke, result/error shapes and the worker's >5 s flight ceiling are unchanged. While a binding call blocks GLib, that child cannot send heartbeats or progress; the independent worker can still restart it via the existing unanswered-heartbeat or flight limit. A fake call remains blocked on the GLib thread while another app submits successfully through the connected parent/child plumbing. Advancing the parent's clock beyond 5 s completes both submissions with `provider_degraded`, kills the fake child and charges neither app. The fake call is released only for test cleanup; no real five-second latency measurement is claimed. |
| F6 — child death accounting and recovery | `wm/worker_tree.py:Provider.down()` now marks known apps degraded with `provider_restarting`, without incrementing breaches or recovery attempts. Existing measured breach history is retained until recovery succeeds. Recovery becomes due at the existing child restart backoff, and uses the existing snapshot/probe path after readiness.
