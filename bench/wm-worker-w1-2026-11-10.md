## Defects found and fixed

### Spec / built-session reconciliation

- The older act spec's bind ceremony expects persisted PID start time and a hashed profile document, and says restart retires the session. Built sessiond stores PID/markers, bare `xvfb|xorg` profile names and the registry paths; the reconciled lifecycle and this task explicitly permit worker restart while applications remain. W1 uses the built record, verifies PID liveness, both markers, session paths, bus addresses and X socket, snapshots `/proc` start time at bind and rechecks it before connecting. It does not invent a persisted identity/profile field or tear down the session on worker stop.
- The generic health example only lists capture modes `mmap|getimage`. Neither exists in W1. Health reports `mode:unavailable, reason:not_implemented` with actual root dimensions, rather than implying capture exists. Provider sample revision/age are null with coverage none; unavailable evidence never yields a guessed predicate result.
- The older observation contract includes complete tree/pixel coverage in the unchanged promise. Here `auto` explicitly means state only, as required by W1. Requesting unavailable channels exposes coverage gaps and `unchanged:null`; those data parts are absent.
- The reconciled dialog rule requires an exact classifier. W1 can evaluate an explicitly supplied exact window title/class classifier together with X dialog/modal/transient evidence. A type-only/default semantic dialog classifier returns unavailable evidence. No Thunar accessibility classifier is claimed before W4.

### Harness

- The initial fake X connection omitted `on_error`; corrected the test double. Also retained the actual fake root object when asserting XI selection had not occurred before negotiation. These were harness defects, not live X failures.
- Read-only registry state, failed Xvfb listening sockets and AF_UNIX EPERM are environment blockers. They were not worked around by changing sessiond or relaxing display bounds.

### Product

- Corrected python-xlib's raw GetProperty `(format,data)` reply decoding; its blocking convenience wrapper normally unwraps that shape.
- Selected client events before sampling metadata, so a title/geometry change during the snapshot cannot escape event coverage. A later event during an outstanding snapshot schedules a refresh; dirty work forbids unchanged.
- Prevented stale snapshot replies from resurrecting a destroyed XID. Kept unmap evidence even when the WM removes the client list entry first; retained removed-handle evidence for scoped observations.
- Consumed expected BadWindow selection races explicitly; other asynchronous X errors reach the fatal path. Added local malformed/truncated control handling and journal-corruption handling.
- Control acknowledgement requires both final epoch and state, so the safe intermediate opening state cannot be acknowledged as AGENT. Closed malformed pages and real state/epoch changes enter the revision cache and sole-writer journal.
- Drained X arrivals and control changes before each decoded RPC, including coalesced frames. Invalid requests return errors; they do not masquerade as missing providers or retire the worker.
- Added stale endpoint/metadata cleanup when stopping an already dead worker, preserving the registry/session. A startup timeout escalates termination of the marked daemon if graceful exit fails.

## Simplifications and implementation limits

- Only the requested W1 slice is implemented. `inp` is opened/held and XTEST version-negotiated but sends no input. No helper connection, self-test, clipboard work, provider child, Damage object, pixel capture/hash, accessibility ref, semantic tree or OCR exists. `window.act` dispatches and journals nothing. All ten specified act counters are present and zero because no act batches execute.
- The daemon has one selectors loop, no threads and no sleeps. Runtime X queries use deferred python-xlib requests, pumped with nonblocking sockets. The initial python-xlib connection/extension setup remains in its connection constructors; subsequent replies never use blocking `reply()`/`sync()`. Disk durability still uses the required synchronous flush/fsync.
- The control page is held as a read-only mapping. W1's ≤50 ms local polling reads it with `pread` twice and verifies path identity/size, avoiding SIGBUS on truncation. Only start/control write it, using aligned little-endian stores in the specified order. An existing page is rebound to the new generation with its prior authority state preserved and epoch advanced.
- Five-second asynchronous state reconciliation is retained from the observation contract; refresh/coverage gaps forbid unchanged. Scope filtering works for window/family/session; the integer unchanged test is conservatively session-wide, so an unrelated change may produce an empty scoped delta rather than an unchanged answer. No X request is added to that comparison path.
- Version reporting uses installed package metadata for Openbox and negotiated X extension versions; no extra version command runs in the daemon. A standalone `openbox --version` diagnostic printed 3.6.1 and a read-only cache-directory warning; no cache directory was created.
- Transport, generation/lease rules, real WM lifecycle, event subscription behaviour, popup attribution, actual event-loop latency and the absence of live fast-path X writes still require independent SSH verification. Static/synthetic checks are not substituted for those gates.

## Fix round 1

Nov 10, 2026, ArK2. Addressed only the three reported startup defects in
`wm/ark-worker`, with regressions in `wm/tests/test_worker_w1.py`. The original
results above remain historical; this round does not claim successful live
startup or acceptance.

### Root causes and fixes

1. **Generic-event dispatch crash.** `XState.events()` previously referenced
   `X.GenericEvent` (original line 664). Installed python-xlib 0.33 defines
   `GenericEventCode` in `Xlib.ext.ge`, not `Xlib.X`. Any event falling through
   the earlier branches could therefore raise AttributeError, even an ordinary
   unhandled event. The original synthetic stream exercised only branches that
   matched earlier and never evaluated this constant. Dispatch now uses
   `ge.GenericEventCode` and ignores all generic payloads in W1, including raw
   byte payloads and unknown extension/subtype combinations. Core window,
   focus, geometry and motion handling remains intact. No broad exception
   suppression was added; genuine X-layer faults still take the `worker_fault`
   path. XI raw-event acknowledgement/decoding remains W2 work.

2. **Root-owned Xorg identity rejection.** The failing sub-check was
   `session_record()`'s `marked(pid_x, state, sid)` (original lines 102–103).
   `marked()` reads `/proc/<pid>/environ` and returns false on PermissionError.
   Sessiond's sudo-launched Xorg is root-owned; a correct registry PID therefore
   failed this test. The previous suite had no real or synthetic X-server bind
   identity test; lifecycle tests bypassed `session_record()`. The replacement
   `verify_x_binding()` requires the session display's Unix X socket, the
   profile's Xorg/Xvfb command name and exact `:display` argument in the process
   command line, and a matching PID in `/tmp/.X<display>-lock`. Bind still
   rejects a dead/zombie PID and snapshots `/proc/<pid>/stat` start time;
   `XState.__init__()` rechecks both start time and display binding before its
   first X connection. These checks require no same-UID ownership or X-process
   environment access. Worker/child exec markers, path/bus checks and the
   91–120 display guard remain enforced. This supersedes the earlier note's
   statement that bind verifies the X server's environment markers.

3. **Failed-start orphan.** The failure-cleanup guarantee was incomplete in
   `Worker.run()`, `cleanup()/begin_stop()` and `start()`: the failed reply was
   sent before cleanup, child termination depended on selector/X teardown
   (including querying potentially broken X connection FDs), and the launcher
   escalated a timeout against the daemon PID alone. The old lifecycle test
   raised during X construction, before any child existed. Cleanup now
   terminates and reaps its Openbox child first, escalates TERM to KILL after
   two seconds, unregisters X FDs from selector records, and reports startup
   failure after cleanup. On any unsuccessful startup reply, EOF, malformed
   reply or timeout, the launcher also terminates the process group it created
   for its daemon and children, escalates to KILL, and reaps the daemon. Existing
   session applications are outside that group. The supplied live report has
   no cleanup traceback, so the exact escape taken by that particular orphan
   is not independently established; the identified cleanup gaps are fixed.
