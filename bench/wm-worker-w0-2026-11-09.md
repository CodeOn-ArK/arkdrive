## Defects and limitations

- **Spec inconsistency:** reconciled build spec R9 says `--broker-uid`, while adopted §4/S2, design §2.3 and this explicit W0 task say `--owner-uid`. Implemented `--owner-uid` per the scoped contract; no design/spec files changed.
- **Harness bugs:** none identified or fixed. Read-only STATE, unavailable privilege elevation, socket EPERM, absent uinput and hidden/unreachable host display are execution-environment blockers. They are recorded as failed gates, not diagnosed as sessiond defects.
- **Product changes/fixes:** implemented the three missing prerequisites. Added stale-socket removal on recycled session ids so an interrupted helper cannot block its replacement. During fixture review, excluded startup focus/crossing from popup triggers, made rejected events return before scheduling side effects, and disabled cursor blinking for the identical-repaint option. The headless callback check covers rejection/popup ordering only; the remaining behaviours need live verification.
- **Open product verification:** no real helper-device lifecycle, socket accept/reply/ownership, Xorg grab, live fixture delivery or accessibility check could be completed here. Successful-start sessiond regression acceptance remains outstanding.

## Simplifications

The original sessiond v0 simplifications remain unchanged. W0 adds only a dormant socket: there is no request schema, bind state, dedupe, pacing, control-page read or input write. Its thread exists only to serve dormant replies without delaying the existing quit FIFO. `--control` is retained as a path, with no control file created. Both fixtures use distro `/usr/bin/python3` with GTK3; canvas text remains entirely in painted pixels. Openbox is a failed prerequisite, not silently substituted.
