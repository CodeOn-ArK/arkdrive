## Built against the numbered scope

1. **Child.** `wm/worker_ocr.py` implements a persistent, restartable child and
   a nonblocking parent supervisor. One `ctypes.CDLL('libtesseract.so.5')` and
   TessBaseAPI instance are created per child lifetime. No Tesseract executable
   is invoked. Settled, source-resolution RGB rows come from W3's existing
   `Pixels.shadow.row` path. A worker-owned memfd supplies the image data;
   inherited local pipes carry W4's bounded, length-framed JSON descriptors
   and results. The child never connects to X, AT-SPI, D-Bus or a GPU. It maps
   the image read-only; its display/bus environment is removed. OMP is limited
   to one thread. Logs use the session's `logs/ocr-provider.log`.
2. **Channel and cache.** Output is `{text, box:[x,y,w,h], conf}` with native
   desktop offsets. Preprocessing is grayscale, bicubic ×2, sparse text, or
   single line for regions ≤48 px high. Word confidence below 60 is dropped
   before joining text and computing line bounds. The line confidence is the
   minimum retained word confidence. Results use SHA-256 of source RGB plus
   region coordinates and parameters, with a 256-entry LRU. The unchanged and
   damage-but-identical paths send no child request. Both issued request counts
   and the real child's completed request count are tested. Explicit legacy
   line/block segmentation participates in the cache key.
3. **Incremental reads.** Row/column content fingerprints locate the changed
   pixel bounding box. Only a horizontal slab, full region/window width and
   24 px above and below the damage, is sent. Old interior lines are replaced.
   Unaffected cached lines crossing/touching a slab boundary are retained;
   clipped OCR fragments at that boundary are dropped in their favor. Cached
   results from an obsolete in-flight image cannot satisfy a read of changed
   pixels. A real-child sequence of 200 partial repaints compares complete
   line dictionaries, including boxes and confidence, with independent full
   rereads. It includes over 100 cases exercising retained boundary lines.
4. **Observation order.** The existing observe pipeline now uses OCR for an
   unusable tree or an explicit OCR request. OCR-class predicates read the same
   provider. A tree-unusable target with fewer than three OCR lines escalates
   to exactly one W3 frame; three or more lines suppress automatic pixels.
   Explicit pixels plus blind escalation still produces one frame. Unchanged
   observations bypass OCR. Fresh reads can wait asynchronously within the
   existing observation deadline. At expiry, an unavailable OCR result degrades
   that response's channel and permits a frame; it does not wait for the region
   budget. W3 capture/frame code itself was not changed.
5. **Predicates and fallback.** Implements `ocr_text_present`,
   `ocr_text_absent` with literal/regex operands and region scope. Also implements
   the already-declared `ocr_text` exact whole-line predicate, with NFC and
   CRLF→LF normalization and existing crop/line/block parameters. Under degraded
   AT-SPI, name-only `node_present`/`node_absent` becomes the corresponding OCR
   predicate; role, ref and semantic container constraints are not guessed.
   `text_equals` on a ref remains unknown with `provider_degraded`. Receipts
   retain the original expectation, record the effective OCR predicate/class,
   `fallback_from: "tree"`, typed OCR evidence with source hash, region, boxes,
   confidence and revision, and `assurance: "visual_state"`. The adapter retains
   assurance/fallback fields in its compact projection. Headless tests include
   a real engine dispatch followed by changed pixels and fallback verification,
   as well as the read-only wait case. Healthy tree predicates retain tree
   evidence and their existing assurance.
6. **Text targets.** `{text,nth,within}` resolves exact accessible names first,
   then OCR lines containing the literal. Multiple matches without `nth`, zero
   matches, or an out-of-range index return `target_not_found`; ambiguity carries
   at most five candidates in the receipt detail. Resolution uses native bounds,
   clips to the window, rejects disabled tree nodes, and rechecks the text
   target before dispatch. Existing geometry/tile/focus/modal guards still apply.
7. **Breaker and health.** A region expires at 1,000 ms, including recognition
   and child preprocessing. A breach, late result, invalid result or process
   death restarts the child immediately and retries the read once. A second
   failure within 60 seconds marks OCR down; probes back off 1, 2, 4, … 30 seconds.
   `system.info.providers.ocr` and observe providers expose state, reason,
   breaches and next_probe_ms. Coverage is tied to the sampled window geometry
   and W3 tile revisions, rather than provider readiness alone. Fault tests
   exercise wedges, crashes, invalid bounds, late replies, recovery and the
   60-second failure window.

### B — degradation bypasses unchanged until fallback is delivered

The OCR decision now examines the target window's tree health even when the
W1 revision fast path says unchanged. A degraded/down publication or readiness
forces `unchanged: false` and engages fallback if OCR has not been delivered
for that tree state and native region. The fallback fingerprint contains
publication status, readiness, breaker breaches and tree freshness. Delivered
OCR is recorded per window in the current lease's observation state, only for
the owning peer; pending/failed reads do not mark it served. A delivered healthy
interval rearms fallback. Crop evidence cannot suppress a subsequent full-window
fallback. Source pixels can stay byte-identical throughout the transition;
their existing OCR cache may satisfy the new delivery without a child request.

Healthy target windows do not enter this override, so their unchanged observes
still issue no OCR read or child request, even with a degraded neighboring app.
No cache revision, tree breaker, input admission, reconciliation or fence rule
was relaxed. Regression tests repeat session observations, degrade the app with
no pixel change, then request that window at the current revision: the first
read waits for OCR, the delivered response contains the hung-window lines, and
the next unchanged read skips OCR. Recovery/redegradation and a degraded
publication during a pending retry are covered separately. Raj's live harness
was read for scenario alignment, not executed.

### C — text evidence requires an alphanumeric character

Drop a line unless `any(character.isalnum() for character in text)` is true.
This Unicode-aware rule preserves letters/digits and punctuation within text,
while removing `(|`, `|`, ellipses, dashes and other symbol-only fragments.
It runs at TSV line construction, glyph-pass output and child-result acceptance
after incremental merging, before caching/evidence/target/predicate consumers.
Consequently those fragments cannot contribute to the three-line threshold.
Tests retain Unicode letters/digits and prove one real line plus two fragments
still yields one text line and exactly one blind-escalation frame.
